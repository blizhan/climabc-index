# Frontend (Climate Index Console)

React + TypeScript + ECharts frontend for climate index observation/forecast visualization.

## What It Shows

- Observation series: solid lines
- Forecast series: dashed lines
- Historical forecast batch selection by **issue month**
- Data snapshot table (observation/forecast rows)
- Bilingual UI (`中文 / EN`)

Default selected metrics in UI:
- `nino34`, `nino12`, `oni`, `soi`

## Data Input

Frontend reads parquet directly at runtime.

Resolution strategy:
- Development: `/data/...` paths served from repo `data/` by Vite middleware
- GitHub Pages: `https://raw.githubusercontent.com/<owner>/<repo>/main/data/...`

Default parquet paths:
- observations: `data/observations`
- forecasts: `data/forecasts`

Supported env overrides:
- `VITE_DATA_BASE_URL` (override runtime parquet base URL)

## Required Parquet Layout

```text
data/
  observations/
    <metric>.parquet
  forecasts/
    _index.parquet
    <metric>/
      <issued_month>.parquet
```

Observation parquet schema (per metric):
- `date` (`YYYY-MM`)
- `value` (number)

Forecast parquet schema:
- `forecast_id`
- `source`
- `issued_date` (`YYYY-MM`)
- `target_date` (`YYYY-MM`)
- `metric`
- `value`
- `is_historical`

Forecast index schema (`forecasts/_index.parquet`):
- `metric`
- `issued_date`
- `source`
- `forecast_id`
- `is_historical`

## Run

```bash
npm install
npm run dev
```

Build:

```bash
npm run build
```

Test:

```bash
npm test -- --run
```

## Export Options

UI export panel supports:
- CSV
- JSON
- PNG (chart snapshot)

These exports are client-side convenience exports and do not replace parquet outputs generated by CLI.

## Deployment Note

- Scheduled data updates commit parquet under `data/**`.
- Pages deployment workflow ignores `data/**` push-only changes.
- Latest page session reads updated parquet directly, so data refresh does not require frontend rebuild.
